KCP 可靠传输协议

类型: 模块概览 状态: 有效 范围: 4 个目录 8 个文件
01. 快速结论
结论先行：KCP 是 QmClient 在 DDNet 原生 UDP 之上叠加的可选可靠传输层，通过扩展消息协商激活。客户端零配置 — 自动跟随服务端。

核心架构：

[Game Protocol CNetConnection/CNetChunk] → [CNetKcpSession/ikcp] → [UDP Socket]

协商流程：服务端通告 SERVERCAPFLAG_KCP → 客户端发送 NETMSG_KCP_CAPABLE → 服务端分配 conv ID 并回复 NETMSG_KCP_ACCEPT → 双方激活 KCP 会话。

┌─ 协商层 ─────────────────────────────────────────────┐ │ 服务端 ──SERVERCAPFLAG_KCP──▶ 客户端 │ │ 客户端 ──NETMSG_KCP_CAPABLE─▶ 服务端 │ │ 服务端 ──NETMSG_KCP_ACCEPT──▶ 客户端 (+ conv ID) │ └──────────────────────────────────────────────────────┘ ┌─ 传输层 ─────────────────────────────────────────────┐ │ VITAL 报文 ──▶ CNetKcpSession ──▶ UDP │ │ Non-VITAL ───▶ 传统 UDP 旁路 ──▶ UDP │ └──────────────────────────────────────────────────────┘

03. 详细分析
混合传输设计

并非所有报文都需要可靠传输。玩家输入快照走 UDP 旁路，游戏状态同步走 KCP。非关键报文绕过 KCP 重传，避免增加尾部延迟。

为什么选 KCP 而不是 TCP

用约 10% 额外带宽换取 30–40% 的 RTT 降低，且不会因单个丢包阻塞整个流。
